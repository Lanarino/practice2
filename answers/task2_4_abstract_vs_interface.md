# Задание 2.4 — Абстрактный класс vs Интерфейс

## Теоретическое напоминание

| Критерий | Абстрактный класс | Интерфейс |
|----------|-------------------|-----------|
| Отношение | «является» (is-a) | «умеет» (can-do) |
| Наследование | Одиночное (`extends`) | Множественное (`implements`) |
| Поля (состояние) | Могут быть любые | Только `static final` |
| Конструктор | Есть | Нет |
| Методы с реализацией | Да | `default`/`static` (с Java 8) |

**Правило выбора:**
- Если есть общие **поля** (состояние) и отношение «является» → **абстрактный класс**.
- Если нужна **множественная реализация** или отношение «умеет» → **интерфейс**.

## Ваша таблица

| Ситуация                                                                           | Ваш выбор         | Обоснование                                                                                                                                               |
|------------------------------------------------------------------------------------|-------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| Все животные имеют имя и возраст, но звучат по-разному                             | Абстрактный класс | Есть общее **состояние** (имя, возраст) и отношение «является» (собака — это животное)                                                                    |
| Некоторые объекты (документ, изображение, настройки) можно сериализовать           | Интерфейс         | Отношение «умеет» (может быть сериализован); разные классы из разных иерархий реализуют одну функцию                                                      |
| Все транспортные средства имеют скорость и топливо, но двигаются по-разному        | Абстрактный класс | Есть общие **поля состояния** (скорость, топливо) и отношение «является» (машина — это транспортное средство)                                             |
| Робот, посудомоечная машина и телефон — все умеют подключаться к Wi-Fi             | Интерфейс         | Нет общего происхождения, но есть общее поведение «умеет подключаться»; множественное наследование поведения                                              |
| Круг, квадрат и треугольник — все фигуры с площадью и периметром, у всех есть цвет | Абстрактный класс | Есть общее **состояние** (цвет) и отношение «является» (квадрат — это фигура); общие поля и логика                                                        |
| Класс должен одновременно уметь летать, плавать и ездить                           | Интерфейс         | Требуется **множественная реализация** поведений; Java не поддерживает множественное наследование классов, но позволяет реализовать несколько интерфейсов |
