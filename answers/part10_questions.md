## Вопрос 1

Что выведет этот код? Объясните порядок выполнения блоков.

```java
class Demo {
    static { System.out.print("A "); }
    { System.out.print("B "); }
    Demo() { System.out.print("C "); }
    public static void main(String[] args) {
        System.out.print("D ");
        new Demo();
        System.out.print("E ");
        new Demo();
    }
}
```

**Предсказанный вывод:**

```
A D B C E B C
```

**Объяснение:**
A — статический блок, он срабатывает самым первым, когда класс загружается.
Потом запускается main: печатает D.
При new Demo(): сначала блок {} → B, потом конструктор → C.
То же самое при втором new Demo() → ещё B C.
В конце E.

## Вопрос 2

Класс `Child` в пакете `b`, класс `Parent` в пакете `a`. `Child extends Parent`. Какие члены `Parent` доступны в `Child`? А какие доступны в другом классе пакета `b`, который НЕ наследует `Parent`?

**Ваш ответ:**
В наследнике (Child) можно использовать:
public и protected поля/методы из Parent.

В обычном классе из того же пакета b (но не наследнике) — только public.
protected виден только в подклассах, даже если они в другом пакете.
А всё без модификатора (default) — только внутри своего пакета (a), так что в b не видно.

## Вопрос 3

Можно ли создать sealed-класс, у которого все наследники — record? Какое преимущество это даёт при использовании в switch?

**Ваш ответ:**
Да, можно. Например:
sealed interface Expr permits Const, Add {}
record Const(int value) implements Expr {}
record Add(Expr left, Expr right) implements Expr {}
Преимущество при использовании в switch:
Так как все возможные подтипы известны компилятору (благодаря sealed), можно использовать pattern matching в switch без default, и компилятор гарантирует, что все случаи обработаны (exhaustive switch). Это делает код безопаснее и чище

## Вопрос 4

Что выведет этот код? Объясните, что такое String Pool и как работает `intern()`.

```java
String a = "Hello";
String b = new String("Hello");
String c = b.intern();
System.out.println(a == b);
System.out.println(a == c);
System.out.println(b == c);
```

**Предсказанный вывод:**

```
false
true
false
```

**Объяснение:**
"Hello" — это строка из пула (особое место в памяти).
new String("Hello") — создаёт новый объект, даже если текст такой же → a == b -> false.
b.intern() ищет "Hello" в пуле и возвращает ту же ссылку, что и a → a == c -> true.
Но b и c — разные объекты -> b == c → false.

## Вопрос 5

Почему этот код не компилируется? Как исправить?

```java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }
class C implements A, B { }
```

**Ваш ответ:**
Ошибка: два интерфейса дают одинаковый default-метод → Java не знает, какой выбрать.
Нужно самим написать метод в классе C:
class C implements A, B {
public void hello() {
A.super.hello(); 
}
}

## Вопрос 6

В чём разница между `StringBuilder` и `StringBuffer`? Приведите конкретный сценарий, когда нужен именно `StringBuffer`.

**Ваш ответ:**
StringBuilder — быстрый, но не для многопоточности.
StringBuffer — медленнее, но работает в нескольких потоках сразу.
Когда нужен StringBuffer:
Когда один и тот же буфер используют разные потоки (например, в веб-сервере).

## Вопрос 7

Что выведет этот код? Объясните, что происходит с переменной `x` в лямбде.

```java
int x = 10;
Runnable r = () -> System.out.println(x);
// x = 20;  // что будет, если раскомментировать?
r.run();
```

**Предсказанный вывод:**

```
10
```

**Объяснение:**
Почему:
Лямбда «запоминает» значение переменной, если она не меняется после присваивания.
Если раскомментировать x = 20; — будет ошибка компиляции, потому что лямбда не может использовать изменяемую переменную.

## Вопрос 8

Напишите пример лямбда-выражения, которое нельзя заменить на ссылку на метод. Объясните почему.

**Ваш пример и объяснение:**
Function<Integer, Integer> f = x -> x * 2 + 1;
Почему нельзя заменить ссылкой на метод:
Потому что такого готового метода (x * 2 + 1) в Java нет. Ссылка на метод (::) работает только если метод уже существует.

## Вопрос 9

Чем `EnumMap` быстрее `HashMap` для ключей-enum? Опишите внутреннюю реализацию в одном предложении.

**Ваш ответ:**
EnumMap просто хранит значения в массиве по номерам enum-элементов (0, 1, 2...), поэтому работает быстрее, чем HashMap, которому нужно считать хеш и проверять коллизии.
